## 1. 계약과 적용 범위

- [x] 1.1 적용 요청을 받은 뒤 현재 Git 상태·manifest·기존 `point-in-time-evidence-gates` tasks와 doctor를 확인하고 새 change에 운영 연결을 갱신한다. 기존 미완료 체크박스와 사용자 보고서가 그대로이며 `work_id`, `active_change`, `next_gate`가 새 적용 범위 및 Git 근거와 연결되는지 확인한다.
- [x] 1.2 버전 있는 사용자 맥락·판단·출처·제약 참조 계약과 입력 검증기를 추가한다. 현재 가격이 유효하고 성과 근거가 `prior_only`인 fixture가 추천 가능하며, NaN·음수·중복 ticker·누락 필수 출처·미래 공시일은 해당 오류로 거절되는지 검증한다.
- [x] 1.3 장기 목표·6개월 평가 기간·1~3년 내 지출 가능성·미상 필요액을 함께 가진 fixture를 추가한다. 중간 맥락과 저장 JSON에 네 정보가 유지되고, 가정한 준비금의 출처가 사용자 확인으로 바뀌지 않으며 결과가 조건부 배분으로 표시되는지 검증한다.

## 2. 독립 분석과 자산 대안

- [x] 2.1 독립 분석 합성 경로에서 새 판단의 근거·반대 의견·중요한 누락을 전달한다. 한 관점 `insufficient`와 두 관점 유효인 입력이 자동 제외되지 않으며 최종 선택 이유와 누락 상태가 저장되고, 서로의 결론을 입력으로 사용하지 않는 실행 계약이 유지되는지 검증한다.
- [x] 2.2 주식과 ETF의 자료 계약을 분리하고 위험 스냅샷에 추가 ETF ticker를 지원한다. ETF의 기업 ROE 미상이 자동 탈락을 일으키지 않고 운용사 자료 기준일·보수·집중도·레버리지 상태가 남으며, 주식과 ETF의 위험 가격 cutoff가 같은지 fixture로 검증한다.
- [x] 2.3 provider 실패·대체 경로·자료 현재성 처리를 새 판단에 연결한다. timeout·인증 누락·quota·stale·수정 자료 fixture에서 실패가 0점/약세로 변환되지 않고, 유효한 다른 후보는 계속 판단하며 전 후보 필수 가격 실패는 현금 100% 성공 대신 `blocked_input`이 되는지 검증한다.

## 3. 최종 비중과 현금 판단

- [x] 3.1 주식·ETF별 상한, 직접 주식 섹터 한도, ETF 포함 전체 노출 제약과 비중 합계 검증을 구현한다. ETF 60%·주식 15%·현금 25% 입력이 회사 상한 때문에 거절되지 않고, ETF 내부 해당 주식 10%일 때 중복 issuer 노출이 21%로 계산되며, 전체 issuer 한도 20% 설정 시 위반을 반환하는지 검증한다.
- [x] 3.2 최종 판단이 가격 가정·비교 대안·하방·반증·비중 이유를 포함하도록 연결한다. 동일 순위 입력에서 근거 있는 서로 다른 판단 비중이 허용되고, confidence의 수익률/성공 확률 변환을 요구하지 않으며 기존 보유 unknown 시 목표 비중만 출력하는지 검증한다.
- [x] 3.3 최종 현금의 목적과 기회비용을 기록하고 새 경로에서 시장 규칙을 참고값으로 전환한다. 시장 목표 10%와 근거 있는 최종 현금 5%의 차이가 보존되며, 상한 후 미배분 잔액을 설명 없이 최종 현금으로 승격하지 않는지 검증한다. 양립 불가능한 사용자 제약은 조용한 재배분 대신 `infeasible`인지 확인한다.

## 4. CLI와 보고서 호환성

- [x] 4.1 `--decision-json`을 새 경로에 연결하고 기존 인자 없는 호출을 legacy로 보존한다. 저장된 기존 입력 fixture의 종목 비중·현금·분석일이 동일하게 재현되고 방식이 구분되며, 새 경로가 기존 점수 배분기를 거쳐 판단 비중을 바꾸지 않는지 검사한다.
- [x] 4.2 검증한 최종 객체로 JSON·엑셀·텍스트를 생성한다. 새 입력의 선택·제외 이유, 가정, 현금 목적, 제약 검사, `weights`, `cash_weight`, `analysis_date`를 JSON 왕복 및 실제 워크북 셀과 텍스트 출력에서 비교해 숫자·상태·근거가 일치하는지 검증한다.

## 5. 추천 보존과 사후 평가

- [x] 5.1 추천 ID별 스냅샷과 입력 무결성 정보를 배타적으로 저장한다. 동일 ID 변경 거절, 새 ID의 이전 추천 연결, 원본 hash 불변, 인증 정보 비저장을 fixture로 검사한다.
- [x] 5.2 같은 거래소 달력의 자산에 대해 최초 비중 매수 후 보유 평가를 구현한다. 장 마감 후 추천 fixture에서 다음 실제 거래일 시가로 시작하고 당일 이전 수익을 제외하는지, 매일 리밸런싱한 결과와 다른 알려진 가격 경로를 손계산 결과와 비교한다. 혼합 달력은 지원되지 않음으로 명시되는지 검증한다.
- [x] 5.3 비교 ETF 총수익·현금 이자·비용·환율·배당 정책을 동일 기간 계산에 연결한다. 분할과 배당이 있는 알려진 경로에서 이중 배당 가산이 없고 자산별·현금 기여 합계가 총수익과 맞으며, 비용 차감·기준 통화와 세전 가정이 결과에 남는지 검증한다.
- [x] 5.4 평가 상태와 버전을 구현한다. 평가일 미도래는 `not_due`, 한 종목 평가 가격 누락/거래 정지/상장폐지는 `incomplete`이며 승자만으로 전체 수익을 산출하지 않는지 검사한다. 수정 자료는 기존 평가를 보존한 새 버전으로 남고 음의 상대 수익도 기록되며 사업 가설 평가와 구분되는지 확인한다.

## 6. 스킬 통합과 완료 검증

- [x] 6.1 predict·독립 investor-analysis·risk snapshot·portfolio-report·backtesting의 관련 스킬 및 참조 설명을 새 판단 흐름에 맞추고 `.agents`/`.claude` 미러를 동기화한다. 실제 실행 예시가 새 판단 입력을 만들며, ETF 자동 우선·OOS 부재만으로 추천 거절·미검증 뉴스의 정량 반영을 요구하지 않는지 문서와 실행 계약을 검토한다. 미러 회귀 대상에 새 파일을 포함한다.
- [x] 6.2 `AGENTS.md`, `README.md`, OpenSpec 규칙과 report 문구를 현재 추천 역할 및 별도 실증 성과 게이트로 일치시킨다. 실제 거래·수익 보장 금지와 기존 미완료 외부 증거 작업이 유지되고, 연구 목적이라는 문구가 추천 전체의 무효 선언으로 쓰이지 않는지 검토한다.
- [x] 6.3 저장 fixture로 새 판단 입력→검증→보고서→스냅샷→사후 평가 전체 경로와 기존 금융 스킬의 영향받는 회귀를 실행한다. 새 순위·성과 향상으로 주장하지 않고 입력·중간 검사·JSON·워크북·평가 결과의 일치를 확인한다. `git diff --check`, OpenSpec strict validation, verify와 doctor 결과를 확인하고 구현·로컬 검증·미실행 외부 자료 및 장기 성과 근거를 구분해 보고한다.
