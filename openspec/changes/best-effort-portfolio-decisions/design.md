## Context

동기는 [proposal.md](proposal.md)의 Why를 따른다. 현재 관찰한 구현과 저장 자료는 다음과 같다.

- `.agents/skills/portfolio-report/scripts/generate_portfolio_report.py`의 `build_candidates`는 독립 의견 중 하나라도 `insufficient`이면 제외하고, 나머지는 bullish 다수결과 `total_score * confidence / 100 * bullish_ratio`로 배분 점수를 만든다. `allocate_weights`는 종목·섹터 상한 적용 후 남은 금액을 현금으로 반환한다.
- 같은 스크립트의 `main`은 시장 국면의 현금 목표를 하한으로 사용한다. 이 구조는 명시적인 투자 판단 없이도 최종 현금이 커질 수 있다. JSON뿐 아니라 후보 선정·배분 함수를 함께 확인했다.
- `portfolios/sp500_20260909`의 입력·중간 자료와 결과에서는 503개 순위, 독립 의견 90건, 위험 자료를 거쳐 4개 종목 49.9%와 현금 50.1%가 남았다. 시장 국면의 현금 목표 약 9.92%와 최종 현금 사이 차이는 별도의 최종 투자 판단을 요구하는 사례다. 이 사례는 새로운 방식의 성과 증거가 아니다.
- `tests/test_financial_skills.py`는 비중·시점·독립 분석·직렬화와 `.agents/skills`/`.claude/skills` 미러를 검사한다. 두 스킬 경로는 실제 별도 디렉터리이므로 함께 관리해야 한다.
- 기존 `point-in-time-evidence-gates`는 역사적 구성 종목·재무 빈티지·팩터 및 뉴스 검증의 미완료 작업을 가진다. 현재 추천 기능의 구현 완료와 이 실증 자료의 확보는 별개다.

## Goals / Non-Goals

**Goals:**

- 현재 실행 중인 AI가 독립 자료를 종합해 추천안을 만들고, 결정론적 코드가 입력·근거 참조·비중·제약·보고서 일치를 검사하는 구조를 사용한다.
- 기존 연구 파이프라인의 근거와 legacy 배분 재현을 유지하면서 주식·ETF·현금을 하나의 최종 판단으로 다룬다.
- 추천 당시 상태를 고정해 수익 결과와 판단의 타당성을 나중에 각각 평가할 수 있게 한다.

**Non-Goals:**

- 검증기가 투자 판단의 최적성이나 설명의 진실성을 자동 증명하는 기능, 새로운 학습 모델·최적화 알고리즘의 대규모 개발.
- 기존 팩터·뉴스 정량 게이트 완화, 과거 구성 종목 데이터 구축, 자동 매매 또는 자동 평가 스케줄 생성.
- 이번 제안 작성에서 운영 매니페스트를 새 작업으로 전환하거나 기존 보고서를 재생성하는 작업.

## Decisions

### 1. 판단 작성과 계산 검증을 나눈다

`portfolio-report`를 최종 판단의 주 역할로 둔다. `predict` 순위와 독립 투자자 분석은 후보와 반대 근거를 찾는 입력이다. 위험 스냅샷까지 수집한 뒤 현재 AI가 버전 있는 판단 JSON을 작성한다. 새 `portfolio-decision` 참조 계약과 스크립트 모듈은 구조·출처 연결·날짜·유한 수치·제약만 검증한다. 독립 관점은 서로의 결론과 최종 추천 비중을 보지 않은 상태에서 먼저 작성한다.

기존 점수 공식을 약간 수정하는 대안은 채택하지 않는다. 점수 척도와 confidence의 임의성이 여전히 자본 배분을 지배하기 때문이다. 새 외부 LLM 서비스도 추가하지 않는다. 이미 스킬을 실행하는 AI가 판단을 담당하며 테스트는 외부 AI 호출 없이 저장 fixture를 사용한다.

### 2. 사용자 맥락과 판단 입력을 버전으로 관리한다

`generate_portfolio_report.py`에 선택 인자 `--decision-json`을 추가한다. 새 스킬의 기본 흐름은 이 인자를 사용한다. 인자가 없는 기존 호출은 결과 비중을 유지하는 legacy 경로이며 출력에 방식만 명시한다.

판단 입력에는 다음 묶음을 둔다.

| 묶음 | 주요 내용 |
| --- | --- |
| 실행 맥락 | schema/version, decision_id, 생성 시각, 자료 cutoff, 기준 통화, 비교 ETF, 전략 목표, 평가 기간 |
| 사용자 맥락 | 지출 시점·필요액·통화, 손실 제약, 기존 보유 또는 unknown, 거래·환전·세금 가정 |
| 자료 목록 | 출처 ID, provider, URI 또는 로컬 참조, 조회 시각, 자료 기준일·공시 가능 시각, 품질·대체·수정 상태 |
| 대안과 판단 | 주식/ETF 구분, 편입·제외 이유, 사실·추론·가정 구분, 가격 가정, 하방·반증 조건, 목표 비중·비중 근거 |
| 현금 | 지출 준비 목적, 전략적 대기 목적, 통화·예상 이자 가정, 대안의 기회비용, 최종 비중 이유 |
| 제약·상태 | 적용 단위가 있는 한도, 계산된 노출, 위반 항목, 추천 상태, 별도의 성과 근거 수준 |
| 평가 규칙 | 비교 대상, 최초 체결 기준, 비용·배당·현금 처리, 예정 검토일과 사건 조건 |

추천 상태는 `ready`, 가정이나 비필수 자료의 한계가 남은 `conditional`, 필수 입력 오류인 `blocked_input`, 양립 불가능한 제약인 `infeasible`로 구분한다. 성과 근거 수준은 별도 필드로 유지한다. `prior_only`가 `blocked_input`을 유발하지 않는다.

입력되지 않은 지출 필요액을 0으로 놓지 않는다. 알려진 1~3년 사용 가능성은 해당 실행의 사용자 맥락에 보존하고 준비금 가정에 따른 조건부 배분을 제시한다. 모든 사용자의 기본 투자 기간을 1~3년으로 바꾸지는 않는다.

### 3. 가격 판단은 계산 근거와 연결한다

종목별로 현재 가격에서 무엇이 기대되고 어떤 사업·가격 변화가 투자 판단을 틀리게 만드는지 작성한다. 가격 범위는 기업의 현금흐름·주당 이익·주식수·평가 배수 등 선택한 방법의 가정과 연결한다. ETF는 추종 자산·구성·보수·통화·집중도에 맞는 분석을 사용한다. 지수 ETF는 비교 대안이며 자동 선택 대상은 아니다.

가격 시나리오는 필요한 경우에만 수치화하고 기간·단위·배당 포함 여부를 명시한다. 숫자의 신뢰도를 뒷받침할 자료가 없으면 범위 또는 정성 판단을 사용한다. 가정 확률을 사용할 때는 주관적 가정임을 표시하고 합계를 검사한다. `score_implied_return_pct`와 투자자 confidence는 기대 수익률·성공 확률의 입력으로 사용하지 않는다.

공시·IR의 확인 가능한 사건을 투자 가설에 반영하는 것과 뉴스 감성 점수를 정량 순위에 반영하는 것은 구분한다. 후자는 기존 뉴스 검증 계약을 그대로 따른다. 새로운 판단 문장이 검증되지 않은 뉴스 점수를 우회 투입하는 통로가 되지 않도록 출처와 사용 목적을 기록한다.

### 4. 자산 유형과 제약 범위를 명시한다

위험 스냅샷에 명시적 추가 ticker 입력을 지원해 비교 및 편입 ETF도 같은 cutoff의 가격 위험 자료를 갖게 한다. 주식 후보 순위는 기존 경로에서 산출하고 ETF는 별도 운용사 자료와 독립 분석 대상으로 추가한다. ETF에 기업 전용 ROE·부채비율 누락 패널티를 적용하지 않는다.

새 판단 경로에서 기존 개별 주식 상한 15%는 변경 가능한 기본 제약으로 유지한다. ETF는 별도 한도를 요구하며, 일반 분산 비레버리지 지수 ETF의 기본 개별 한도는 100%로 두어 단일 ETF 포트폴리오도 표현할 수 있게 한다. 집중·레버리지 상품에는 이 기본값을 상속하지 않고 명시적인 제한과 판단을 요구한다. 이 숫자들은 경험적으로 최적이라고 추정한 비중이 아니라 명시적인 운용 정책이다. 사용자 제약은 이 기본값보다 우선하며 최종 판단에서 기본값 조정이 필요하면 이유와 변경값을 기록한다.

기존 섹터 상한 35%는 직접 주식 포지션의 전체 포트폴리오 대비 합계에 적용한다. ETF 구성 종목까지 합친 issuer·sector 노출은 별도로 계산해 보고하며, 전체 노출의 한도를 사용하는 경우 입력에 범위와 값을 명시한다. ETF를 하나의 회사나 하나의 섹터로 취급하지 않는다. 운용사 구성 자료는 기준일·커버리지를 갖고, 필수 look-through 한도를 검증할 자료가 없으면 통과 처리하지 않는다.

검증기는 비중을 몰래 재분배하지 않는다. 위반 목록을 받아 AI가 판단안을 수정한다. 합계는 표시 단위에서 100.00%가 되어야 하며 반올림 조정도 기록한다. 경제적인 미배분 잔액과 표시 반올림 잔액을 구별한다.

### 5. 현금은 최종 판단의 일부다

기존 시장 국면의 현금 목표는 새 경로에서 참고값으로만 전달한다. 최종 현금은 사용 시점·필요액, 시장 위험, 개별 기회의 매력, 현금 보유의 수익과 기회비용을 함께 판단한다. 적용한 참고값과 다르면 이유를 남긴다. 현금 0%나 100%도 판단 근거와 제약이 허용하면 표현할 수 있다.

후보 수가 적거나 종목 상한으로 잔액이 발생하면 ETF를 포함한 대안을 검토하고 최종 판단을 다시 작성한다. 빈 후보를 현금 100% 성공으로 바꾸는 기존 처리는 legacy에만 남긴다. 모든 필수 가격이 실패한 새 경로는 `blocked_input`으로 끝난다.

### 6. 자료의 충분성과 성과 주장의 충분성을 구분한다

현재 추천은 유효한 현재 자료와 명시적 가정으로 내릴 수 있다. 일부 분석의 `insufficient`는 그 관점의 한계이며 자산 전체의 자동 거절 사유가 아니다. 중요한 사실의 공백인지 최종 판단에서 설명한다. 반면 비정상 가격, 잘못된 식별자, 미래 공시일, 필수 제약 검증 불가능 상태는 실제 입력 오류다.

현재성 정책은 자료 종류별 허용 시차와 실제 최근 거래일을 입력에 기록한다. 재무 결산일·공시일·조회일을 분리하고 최신 값의 사후 수정 가능성도 보존한다. 인증·timeout·quota 실패의 대체 provider는 명시적으로 남긴다. 최신 자료를 과거 빈티지로 주장하지 않는다.

`AGENTS.md`, `README.md`, 관련 스킬 및 `openspec/config.yaml`의 표현을 현재 추천 허용과 경험적 성과 주장 게이트로 정리한다. 기존 보고서의 “실제 투자 결정의 근거가 될 수 없습니다”라는 일괄 부정은 “현재 자료와 가정에 따른 연구 목적의 추천이며 미래 성과는 미확정”이라는 역할 설명으로 교체한다. 실제 주문·자금 이동과 성과 보장 금지는 유지한다.

### 7. 보고서는 검증한 하나의 객체에서 만든다

새 판단을 검증한 후 같은 객체로 JSON·엑셀·텍스트를 생성한다. 기존 소비자의 `weights`, `cash_weight`, `analysis_date`는 유지하되 `methodology`, 판단 상태와 근거 참조를 추가한다. 엑셀에는 최종 배분·선택 이유·가정·비교 대안·제약 검사·평가 예정 정보를 넣는다. JSON 저장 후 재로딩 결과를 비교해 유실을 검사한다.

legacy 경로는 기존 fixture의 비중과 기존 필드를 보존한다. 추가 필드와 문구로 새 방식과 구분한다. 과거 결과 파일을 새 방식으로 덮어쓰지 않는다.

### 8. 사후 평가는 먼저 작은 범위로 구현한다

추천 스냅샷은 새 decision_id의 디렉터리에 배타적으로 생성한다. 정규화한 판단 JSON과 참조 가능한 입력의 SHA-256, 생성 시각, 버전을 manifest에 남긴다. 인증 정보와 재배포할 수 없는 provider 원문은 저장하지 않고 출처·시각·무결성 참조만 남긴다. 같은 ID의 내용 변경은 거절하고 새 결정에는 이전 ID를 연결한다.

첫 구현은 개별 추천의 최초 목표 비중으로 매수 후 보유하는 평가다. 매일 원래 비중으로 재조정하는 계산과 구별한다. 기존 backtesting의 구성 후 평가·거래일·비용 처리 코드를 확인해 재사용 가능한 계산만 가져온다. 새 전략을 선택한 과거 기간으로 소급 실행하지 않는다. 시작은 `max(decision_created_at, input_cutoff)` 이후의 첫 거래소 정규장 시가이며, 포트폴리오와 비교 지표에 같은 규칙을 적용한다. 첫 범위는 동일 거래소 달력의 자산으로 제한하고 혼합 달력 입력은 지원되지 않는 상태로 명시한다. 실행 경로 전체의 여러 리밸런싱 실적은 별도 연결 엔진이 있을 때만 주장한다.

가격·배당·분할 자료는 처리 방식을 기록한다. 총수익 조정 가격을 사용하는 경로에서는 배당 재투자 가정을 명시하고 배당을 중복 가산하지 않는다. 원가격·배당 경로를 사용할 때도 같은 배당 정책을 따라야 한다. 거래 비용과 환전 가정, 현금 이자 가정을 양쪽 계산에 일관되게 적용한다. 사용자별 세금이 알려지지 않으면 세전 기준임을 명시한다. 상장폐지·거래 정지·누락 가격은 임의 매도나 0 수익으로 바꾸지 않는다.

평가 결과는 새 버전으로 저장하며 전체·자산별 수익, 비교 지표 차이, 관측 기간의 위험, 현금 기여와 사업 가설 검토를 구분한다. 만기 전 평가는 `not_due`, 자료 부족은 `incomplete`로 표시한다. 부정적 결과도 보존한다. 단기 하락에 따른 자동 전략 변경 또는 새 스케줄은 만들지 않는다.

### 9. 운영 연결은 적용 시작 때 전환한다

사용자가 적용을 요청한 다음 `work_id`, `active_change`, `next_gate`를 이 change 및 Git 근거와 연결한다. 기존 `point-in-time-evidence-gates` 작업은 완료 처리하거나 제거하지 않는다. 해당 미완료 항목은 경험적 성과 주장에 필요한 근거로 남긴다. 이 변경의 완료 조건은 구현·해당 로컬 검증·보고서 일치이며, 장기 초과수익 입증이 아니다.

시작 시 doctor의 `PLUGIN_CAPABILITY_REGISTRY_DRIFT` 1건은 별도 제어면 경고다. 기능 테스트 성공으로 이 경고를 해소한 것으로 보고하지 않는다. 이번 계획 작성만으로 작업 연결을 전환하지 않는다.

## Risks / Trade-offs

- 설득력 있는 설명이 실제 우위로 오해될 위험 → 출처가 있는 사실·가정·판단·성과 근거를 구분하고 비교 대안과 반증 조건을 의무 기록한다. 설명 길이로 비중을 늘리지 않는다.
- AI 판단의 실행 간 차이 → 입력·모델 또는 세션 식별 정보·선택 이유를 고정하고 변경 이유를 기록한다. 결정론적 검증은 계산과 계약의 일관성을 보장하는 범위로 한정한다.
- ETF의 큰 비중과 직접 종목 중복 → 자산 유형별 한도와 합산 노출을 별도 검사하며 구성 자료의 기준일과 불완전성을 표시한다.
- 지출 정보 부족 → 조건부 배분을 허용하되 가정과 알려진 제약을 명확히 유지한다. 장기 전략 목표로 생활자금 제약을 지우지 않는다.
- 예측 검증을 추천의 전제에서 분리하면서 과장된 주장이 늘 위험 → 문구뿐 아니라 직렬화 상태와 회귀 검사로 추천 가능성과 성과 입증을 분리한다.
- legacy 경로 유지 비용 → 새 판단 경로와 계산기를 분리하고 기존 fixture 재현을 회귀 기준으로 둔다.

## Migration Plan

1. 적용 요청 후 운영 연결을 갱신하고 versioned 판단 계약·검증기를 추가한다.
2. ETF 위험 입력과 새 보고서 경로를 추가한다. 기존 인자 없는 CLI 동작은 유지한다.
3. 추천 스냅샷 및 고정 비중 사후 평가를 추가하고 자료 실패·시점·비용 회귀를 검증한다.
4. 관련 스킬과 두 미러, 설명 문서를 새 기본 흐름으로 맞추고 로컬 fixture로 전체 경로를 검증한다.
5. OpenSpec verify 후 구현·로컬 검사·미실행 외부 자료/장기 성과 게이트를 구분해 보고한다. 되돌릴 때는 스킬의 기본 호출을 legacy로 복구하고 새 스냅샷은 보존한다.
