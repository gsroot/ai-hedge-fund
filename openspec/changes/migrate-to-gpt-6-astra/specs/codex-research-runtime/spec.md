## Purpose

스킬 기반 투자 연구를 수행하는 Codex의 기본 모델과 작업 지속 원칙을 명확하게 지정하고,
독립 분석·구조화된 산출물·금융 증거 경계를 유지하면서 설정 검증과 실제 모델 검증을 구별한다.

## ADDED Requirements

### Requirement: 프로젝트 Astra 기본값

프로젝트는 GPT-6 Astra를 기본 모델로 제공하고 기존 `xhigh` 추론 수준을 유지해야 한다(MUST).
전역 인증, provider, 승인 정책과 다른 플랫폼의 명시적 모델 선택을 변경해서는 안 된다(SHALL NOT).

#### Scenario: 프로젝트 설정을 적용하는 새 Codex 세션
- **WHEN** 프로젝트를 신뢰하며 상위 우선순위의 모델 override 없이 새 세션을 시작한다
- **THEN** 프로젝트 설정은 `gpt-6-astra`와 `xhigh`를 제공한다

#### Scenario: 실제 런타임 설정을 확인할 수 없는 경우
- **WHEN** 세션 override 또는 신뢰 상태 때문에 적용 여부가 확인되지 않는다
- **THEN** 설정 파일의 존재만으로 실제 모델 사용을 단정하지 않고 확인되지 않은 상태를 표시한다

### Requirement: 승인된 연구의 완결성과 독립 분석

연구 요청은 주어진 자료와 명시적 가정으로 가능한 작업을 완료해야 하며(MUST), 중요한
누락 정보만 질문해야 한다(MUST). 관점별 분석은 다른 관점의 결론과 최종 비중을 입력으로
사용해서는 안 되며(SHALL NOT), 보고서는 정해진 JSON 계약과 유효한 사용자 제약을 따라야 한다(MUST).

#### Scenario: 앙상블 분석
- **WHEN** 여러 투자자 관점에서 같은 후보를 분석한다
- **THEN** 각 관점에는 원자료·기준일·사용자 제약만 제공하고 결론 수집 후 종합한다

#### Scenario: 누락 자료 또는 과거 자료
- **WHEN** provider timeout, 자격 증명 누락, stale 또는 수정 자료를 만난다
- **THEN** 실패 상태와 시점을 명시하고 현재 자료를 과거 자료로 위장하거나 미검증 수익을 보장하지 않는다

### Requirement: 현재 실행 경로와 증거 구분

프로젝트 안내는 현재 금융 스킬 진입점을 제공해야 하며(MUST), 삭제된 코드에 의존하는
레거시 웹앱을 실행 가능한 Astra 통합으로 표시해서는 안 된다(SHALL NOT).
로컬 계산 검증과 실제 모델·provider·성과 검증을 구분해야 한다(MUST).

#### Scenario: 스킬 기반 뉴스 분류
- **WHEN** 뉴스 분류 작업을 준비하고 집계한다
- **THEN** 분류는 현재 세션 모델에서 수행하며 Python에 별도 LLM API 호출을 추가하지 않는다

#### Scenario: 로컬 검사 완료
- **WHEN** 설정 파싱과 기존 금융 회귀 테스트가 통과한다
- **THEN** 로컬 검증 완료로 기록하며 모델 판단 품질, 실제 금융 데이터 조회 또는 투자 성과 개선의 증거로 사용하지 않는다
